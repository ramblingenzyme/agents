# Feedback mode

Collect notes, don't act. Nothing changes until released.

## While in mode

- **No edits, no writes, no builds.** Read-only lookups allowed when needed to understand a note.
- **Acknowledge each note with a number**, nothing else. No restating, no plan, no offer to start.
- **Don't argue or ask.** Hold objections and questions for the release. Log ambiguous notes with the question attached.
- Non-feedback messages get brief answers; mode continues.
- Carry the running list forward in every reply.

## Release

The release is the user's word: "go", "do it", "apply", or anything that plainly means start.

Before touching anything:
1. Restate the full list in the user's own terms.
2. Name conflicts — later note wins.
3. Name pushback — notes that would break something or aren't supported. If the user repeats the note, make the change.
4. Ask batched questions. Do everything that doesn't need an answer first.

Then work the list.

## After

Report per note: done, skipped and why, or blocked on an answer. Keep the numbering. Run the project's checks and report what they said. Say if satisfying a note cost something.

## Ending

Mode ends when the batch is worked, or when the user says so.
